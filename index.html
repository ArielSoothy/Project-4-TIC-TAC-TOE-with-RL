🔍
Why Q-Learning underperforms despite 1M episodes. The training cell uses lose_reward = 0 — meaning the agent gets no penalty for losing. With nothing to avoid, gradient updates only pull toward winning states, and the value function never learns to defend. The saved Q-table converges to ≈50% W / 37% L / 13% T (notebook's own pie chart, reproduced by re-running the eval over 5×100 games: 45/43/12 mean). Fixing this would mean lose_reward = -1 and a retrain. Kept here as-is because it's a real, instructive result.

Win rates compared

Monte Carlo · α sweep

Four configurations were tried. α=0.001, ε=0.1, 5kep → 69%; α=0.01, ε=0.1, 5kep → 91% (best); α=0.001, ε=0.3, 5kep → 85%; α=0.001, ε=0.1, 10kep → 87%. Higher LR helped more than more episodes.

DQN vs DDQN

Both networks share a 9→64→32→16→9 architecture and 32-batch replay. DQN ended at 87% / 13% ties; DDQN at 82% / 18% ties. Decoupling action-selection from value-estimation didn't help here — likely because 100 episodes is too short for DDQN's stabilization benefit to matter.

State coverage

After 1M episodes, Q-Learning visited 2,776 unique board states; 2,261 have non-zero learned Q-values. Of the unreached states, most are positions that never arise when X opens with a deterministic policy — symmetry canonicalization would compress the table further.

How each agent learns

Three RL families, one tiny world.

Patient

Monte Carlo

Plays an entire game, then updates value estimates for every visited state using the final return. No bootstrapping. Slower per-episode, but theoretically unbiased.

V(s) ← V(s) + α · (G − V(s))
Bootstrapping

Q-Learning

Updates after every move using temporal-difference learning. Faster wall-clock convergence, biased by current estimates but fast to improve.

Q(s,a) ← Q(s,a) + α[r + γ·max Q(s',·) − Q(s,a)]
Deep

DQN & DDQN

Neural network (9 → 64 → 32 → 16 → 9) approximates Q-values. DDQN decouples action selection from value estimation to reduce overestimation. Both are heavily undertrained at 100 episodes — would need 10k+ to be competitive on this state space.

Honesty

The honest list of "what's not great here".

✓ Real

  • All four algorithms have working training loops with the correct update rules (Bellman for Q-Learning, first-visit MC, experience replay for DQN/DDQN, target-network split for DDQN).
  • Q-Learning trained for 1,000,000 episodes — saved Q-table is 175 KB, holds 2,776 unique states, 2,261 with learned values. The 1M-row training log is preserved alongside it.
  • All win rates above are reproducible from artifacts in models/ — re-verified by re-running the eval cell post-hoc.

✗ Needs work

  • Q-Learning reward bug. lose_reward = 0 in the training cell — losing isn't punished. Result: 1M episodes converge to ≈50%, not the 90%+ a healthy setup would reach. Left as-is to surface the lesson.
  • Training opponent = random. No self-play, no curriculum. Numbers above mean "beats a random move-maker", not "beats a human".
  • No symmetry canonicalization — rotated/reflected boards are treated as separate states, inflating the Q-table by ~8×.
  • The playable demo below uses Minimax, not the trained models. Exporting the Q-table to JSON + a JS lookup would close this gap in ~40 lines.
